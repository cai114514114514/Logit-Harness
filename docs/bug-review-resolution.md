# Bug review 核实与修复

日期：2026-10-23。对照用户提供的 `docs/bug-review.md`，通过当前源码、供应商文档和
本地可重复的负对照检查核实。原始报告保持原样；以下结论区分已修复路径与保留的限制。

## 1. 请求失败与预算结算：确认，但限定范围

连接未建立、明确的请求拒绝和提交后结果未知，原来都可能按整个预留记为不确定。
另外，代理返回 429 时，内部三次重试再叠加运行器三次重试，会产生九次 HTTP 请求，却只
预留三笔金额。本地夹具复现了这两种情况。

现在提供带类型的请求结果，金额与会话 token 共用用量判定：确定未提交的请求释放预留；
官方 HTTPS 端点返回完整、结构化的 400/401/402/422/429 请求拒绝，且没有相矛盾的
usage/response/output，才按零用量处理。代理错误、未知 4xx、5xx、流中断及已发送后取消
仍保留不确定费用。代理重试每次独立预留，不能藏在同一笔额度内。

这是依据[官方错误原因](https://api-docs.deepseek.com/quick_start/error_codes/)与
[按 token 计费](https://api-docs.deepseek.com/quick_start/pricing/)作出的有限推断，
并非供应商承诺“所有失败请求免费”。403/404 没有被一概释放。不可重试错误会停在保存好的
状态并给出中文恢复操作，不会重复要求模型自己修复密钥。同地址的已保存密钥更新后，需要
先 `/stop`、等待已停止，再 `/resume`，让新后台读取密钥；改变 API 地址使用 `/new`，
已有会话保持原配置。环境变量密钥的改变需要重新启动 CLI。

**历史账本没有改动。** 过去未返回 usage 不等于供应商确认未计费，不能借修复静默清除
历史不确定项或重新获得实验预算。本轮没有付费模型请求。

## 2. web_fetch IPv6 绕过：确认并修复

旧代码对带方括号的 IPv6 `host_str()` 做 `IpAddr` 解析，失败后误按域名放行。
现在按 URL 的类型化 host 处理，并先归一 IPv4-mapped IPv6。环回、私网、链路本地、
ULA 和 metadata 字面量在消耗配额、预留金额之前被拒绝；公网 IPv6 仍能正常提交。
这不声称控制供应商抓取时的 DNS 或重定向。

## 3. 浏览器非公网访问：部分确认并修复

原报告将 `[::1]` 的开发页访问也算作缺陷，与既有“本地开发自动执行”设计不符。
本轮保留显式 localhost 和环回开发地址；阻止已知 LAN、链路本地、ULA、metadata 等目标。
地址检查在启动 Chrome 前执行，同时对页面 HTTP(S) 重定向、脚本、图片、iframe 和 fetch
请求使用 CDP 拦截；inspect 读取前也复核当前页面地址。

真实临时 Chrome 的负对照曾向自有受限地址夹具发出五种请求；修复后计数为零，本地开发页
和既有源站授权仍通过，测试拥有的 Chrome 已退出。

这是应用层的已知地址筛查，**不是完整网络沙箱**：DNS 预检查没有固定 Chrome 最终连接的
地址；独立 worker、WebSocket/WebRTC、弹窗及所有浏览器后台流量不在保证范围内。
环回开发访问仍然允许，包括跨源页面的环回请求；本轮没有引入“仅允许受管理服务”的策略。

## 4. IPC 异常跳过资源关闭：确认并修复

套接字正常意外退出、返回错误、任务 panic、发送停止控制失败以及某个资源关闭失败，原来
可能跳过后续清理。现在由统一监督流程停止接收控制、等待运行器结算写入，然后依次尝试
关闭服务、Chrome 与 MCP，保留原始错误和后续清理错误，避免重复等待已完成的 JoinHandle。

回归检查使用真实临时监听器、任务与停止后落盘的文件，证明停止信号、任务结束和资源关闭
的顺序。运行器不会被任意强杀。进程被杀、外部丢弃整个 serve future、资源自身永不返回
等情况不因此获得退出保证。

补齐 Unicode 安全的按词移动/删除与行内编辑，按键立即重绘。读取工具也明确标注
`limit` 为 UTF-8 字节数，默认 32768，避免把 1 或 5 当成行数反复读取。
