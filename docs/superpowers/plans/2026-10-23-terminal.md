# loh 协作优先终端 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将用户选择的 B 方案实现为可读、可切换成员、保持原生历史的真实 loh 终端。

**Architecture:** 沿用一个 `Screen`、一个事件投影和正常终端缓冲区。先分离记录与摘要展示，
再拆分成员栏、状态、菜单和输入布局，最后验证活动区与已提交历史的交界。只增加客户端
展示状态，不新增 IPC 协议、模型请求、执行内核或平行渲染器。

**Tech Stack:** Rust、Ratatui、Crossterm、现有 Tokio IPC；Python pexpect/pyte/Pillow PTY 检查。

**Spec:** `docs/superpowers/specs/2026-10-23-terminal-design.md`（全文已确认）。

## Review Focus

1. 同名成员/长中文标题/归档旧目标：当前身份仍可区分，不能显示新团队或截断控制范围（Task 2）。
2. 先收到 Applied 后到本地 Accepted：不得重新出现待处理，也不能清掉其他成员状态（Task 1、3）。
3. 已折叠内容包含失败、取消或源截断：摘要仍明确告知，完整原文可搜索和复制（Task 1）。
4. 成员切换时目录菜单、回执与请求迟到：结果回原视图，当前草稿不变（Task 3）。
5. 窄窗口开关菜单、详情中缩放、结算发生在同一帧：历史不重播、不插空洞、输入不残留（Task 3）。

- [ ] **Step 1 — 写行为 RED。** 在现有事件 fixture 上增加：`successful_read_is_one_summary_line`
  断言普通视图只有一条非空步骤摘要、详情包含全文；`failed_read_keeps_error_and_source_limit`
  断言失败和截断同时可见；`summary_never_crosses_origin_or_response` 断言不同归属不合并。
  相同成员/版本/回合/响应的四个成功只读条目最多三行并有“更多”入口；失败命令尾部最多
  四个视觉行且退出码不丢。不以修改旧预期取代新的失败复现。

- [ ] **Step 2 — 增加回执乱序 RED。** 重用真实 Request/Receipt 构造：Accepted→Pending→Applied
  过程中用户原文在普通历史只出现一次；Pending 留在 `pending_lines`，Applied 后为空；
  Applied→迟到 Accepted 仍为空。Failed/unknown 在普通历史保留原因与原文恢复入口。
  同文不同 request ID 保持两次独立输入。完整详情始终含回执来源、目标与版本。

  Step 1 的最小可运行例子，放入已有 `tests/transcript.rs`，复用该文件的 `event` helper：

  ```rust
  #[test]
  fn successful_read_is_one_summary_line() {
      let mut p = Transcript::default();
      p.receive(&event(1, EventData::ActionStarted {
          id: "read-a".into(), tool: "read_file".into(),
          arguments: json!({"path":"calc.py"}),
      }));
      p.receive(&event(2, EventData::ActionFinished {
          id: "read-a".into(), success: true,
          result: json!({"content":"complete source body"}),
      }));
      let rows = p.drain_settled(80);
      assert_eq!(rows.iter().filter(|r| !r.to_string().trim().is_empty()).count(), 1);
      assert!(rows.iter().any(|r| r.to_string().contains("calc.py")));
      assert!(p.entries()[0].full_text().contains("complete source body"));
      assert!(p.drain_settled(80).is_empty());
  }
  ```
