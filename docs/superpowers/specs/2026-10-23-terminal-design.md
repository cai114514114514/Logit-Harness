# loh 终端重设计：协作优先

2026-10-23。用户已选择浏览器对比稿中的 **B：协作优先**。
本文把该视觉方向补全为可实施的终端行为；新增细节标为实施默认值，待全文确认。
现有团队行为继续以 [团队设计](2026-10-23-team-design.md) 为准。

## 目的与依据

用户认为当前 CLI 不美观，曾多次反馈输入后位置跳动、看不出正在做什么、工具历史混乱。
本轮目标是让用户同时看清当前对话、成员分工和实际进展，并能自然地输入、切换、追问。

已实际观察 Claude Code 2.1.309 接 DeepSeek 的三轮问答，包含三次文件读取、一次失败测试、
详情展开和继续追问；另观察 Codex 0.159.3、OpenCode 1.3.2 的本地命令菜单。
Cursor 停留在启动动画，Gemini 停留在目录信任后的重启阶段，不将其算作完整问答参考。
记录位于 `artifacts/terminal-research-2026-10-23/findings.md`。

用户选择 B 的具体内容：成员切换常驻、保留步骤摘要；沿用蓝色 L、Rust 核心、DeepSeek、
后台执行、原生终端历史和已有多智能体能力。本轮不改变任务调度、权限、模型或验收规则。
浏览器中的卡片尺寸、鼠标按钮和字体是设计演示，不是要求加入 GUI 或终端模拟器。

## 界面结构

普通界面使用一个正常终端缓冲区，已结算的对话进入原生历史；下方活动区依次容纳：

1. 当前团队/视图标识和成员栏。
2. 尚在输出的回答或工具预览。
3. 当前动作、真实阻塞原因或需要用户处理的事项。
4. 临时菜单、输入框及一行辅助信息。

成员栏常驻于这个活动区，而非固定在终端物理顶部；已结算历史位于活动区之前。
这是将浏览器 B 布局映射到原生滚动的实施默认值。正常聊天不切换全屏缓冲区、不维护
另一套滚动历史；已有 `/history` / Ctrl-O 详情浏览器仍可临时全屏。

### 启动与普通对话

- 保留蓝色 L，启动区收敛为标识、模型/目录和一句输入提示。无密钥时明确指向 `/setup`。
  最近会话通过 `/sessions` 查看，不在启动区展开一串历史任务。
- 第一次进入对话后启动标识只进入历史一次，切换视图、打开菜单、缩放和重连不反复插入。
- 尚无团队时隐藏成员栏，不显示占位成员、空任务编号或“并发 2”。
- 提交立即反馈到当前视图：本地发送中、已持久接收待处理、开始响应各有明确状态。
  问候的结束文案是“等待输入”；工程完成仍由运行时独立验收决定。

### 团队与成员栏

- 有团队时固定显示主控、当前成员及可容纳的其他成员，带简短状态：执行、等待、暂停、
  完成；选中项使用蓝色和选中符号，不仅依赖颜色。
- 稳定按成员身份排序，不随进度时间或消息到达频繁换位。当前成员始终可见，超出宽度用
  `+N` 和 `Ctrl-T` 提示进入完整团队列表；窗口数量不影响成员或并发数。
- `Ctrl-T` 打开现有团队选择器，上下选择、Enter 聚焦、`o` 打开窗口、Esc 返回。
  `/agent`、`/agent main`、`/agent NAME --window` 与手动 attach 的含义不变。
  不占用编辑器的 Tab 补全或左右移动，也不要求鼠标操作。
- 主视图保留成员里程碑与短摘要，成员完整工具流仍只在成员视图/详情显示。
- 成员视图持续显示可辨认的团队、成员、当前任务及“仅控制此成员”；归档视图显示
  “归档只读”和原团队。团队名称从当前目标取短标题，重名或歧义时附短 ID；完整 ID
  总能在 `/status`、`/team` 和详情找到。不得用当前新目标替换归档团队标识。
- 切换视图先显示一次轻量分隔，再显示目标视图尚未展示的内容。任务重新分配有独立
  任务标题分隔。草稿及在途请求仍绑定原团队、成员和分配版本，过期草稿醒目提示并保留。

## 对话、步骤与详情

### 正文

- 用户输入使用统一提示符；回答左对齐，段落之间一空行。正常正文保持终端前景色，
  蓝色用于当前视图/选中项/活动状态，弱化信息使用次级色。
- 标题、列表、行内代码和代码块保留明确层次。代码缩进、命令文本及错误原文不改写；
  不把模型原文中的状态词当作系统状态。
- 正常界面不在每行重复时间、Actor、回合 ID、任务版本。详情保留准确归属和时间。
- 保留用户终端背景、`NO_COLOR` 和文本符号回退。截图采集器的 CJK 字体不属于产品字体。

### B 方向的步骤摘要

B 保留每个执行步骤的可辨认摘要，不采用 A 那种只剩一个累计计数的默认展示：

| 类型 | 普通视图 | 详情 |
|---|---|---|
| 文件读取 | 状态 + `读取 calc.py` + 必要范围 | 原文、行号、来源截断说明 |
| 搜索 | 状态 + 查询/目录 + 结果数量（实际可得时） | 完整命中与路径 |
| 修改 | 状态 + 文件 + 实际新增/删除统计（可得时） | 补丁、冲突与校验结果 |
| 终端 | 实际命令摘要 + 执行状态/退出码 | 原始输出、进程信息 |
| MCP/浏览器/联网 | 工具及关键对象 + 真实结果摘要 | 参数、调用结果及来源 |

- 默认成功步骤占一行；文件读取不再每次附几行文件内容，避免挤开回答。
- 同一响应内连续的成功只读步骤可在展示上成组，但每个路径/步骤仍可辨认，组内最多
  三行，更多显示数量及详情入口。不同成员、任务版本、回合或响应不能混成一组。
- 失败、取消、未知结果与输出源截断不能被成功统计吞掉。失败命令直接露出退出码及
  必要错误尾部（默认至多四个视觉行），完整原文留在详情。成功读取与测试失败分别标识。
- 并发结果按现有结算顺序追加，不为凑成一组拖延已经可展示的错误或结果。
  分组仅限本次待提交的相邻条目；已写入原生历史的条目不回写、不再次追加。
- 运行中的步骤显示当前对象与活动状态，工具结算后由同一条记录变成最终摘要。
  流输出、迟到结果及取消继续按既有事件身份关联，不另造一套展示用事件事实。
- 原生历史中的已提交摘要通过 Ctrl-O 或 `/history` 进入完整详情；浏览器演示的“展开”
  不要求原地回写终端历史。详情仍支持逐项展开、分页、搜索及超过 300 条的完整检索。

## 状态、回执与输入

- 常态只显示当前实际动作；等待时说明具体原因及对象，必要时显示最后进展时间。
  不能用“正在理解”覆盖工作区被占用、等待成员、用户暂停、授权或请求失败。
- 需要操作的信息优先于普通计时：旧草稿/送达失败、授权/待答问题、暂停或停止结算、
  工作区等待、执行活动。多个问题显示数量与完整入口，不裁断唯一可用的操作命令。
- 常规 Accepted/Applied 回执只更新活动状态，不永久追加两条“已接收/已应用”系统行。
  用户输入只出现一次。未应用时“已接收，等待处理”保持可见；失败和结果不确定保留
  一条可追查记录、目标和原文恢复入口，不伪装成成功。
- 普通系统诊断（分类完成、内部边界已结算）进入详情；分派、交接、阻塞、纠正生效、
  暂停、恢复及最终验收结果继续保留可读的里程碑。
- 用户文本、模型响应、工具记录及协作消息各自归属不变。收到消息不等于已执行，任务
  完成不等于模型结束，隐藏普通回执不影响运行时完成屏障。
- 输入区保持一套编辑器：Enter 提交、Alt-Enter 换行、粘贴不自动提交，中文/组合字符、
  历史与多行移动保留。切换成员和开关菜单不得清空、误投草稿或改变执行模式。
- Ctrl-C 和 `/pause` 在主控控制整队、在成员视图仅控制该成员；整队恢复不解除局部暂停。

## 命令、用量与尺寸

- `/` 菜单继续使用唯一命令目录，保持全部已有命令、Skill 来源与执行时机。命令名和
  简短描述对齐；选中项再显示来源/执行时机，不为每个菜单项重复附上一长串标签。
- 本地查看、焦点切换与菜单不调用模型。原任务仍通过 `/new` 留在后台。
- B 的底部信息保留当前模型、当前视图的累计 token 和真实 KV 命中；主控代表团队总账，
  成员代表该成员。缺少 Usage 显示未知，不显示虚构的 0% 或精确费用；细账用 `/usage`。
- 宽窗口显示完整提示，窄窗口依次收起次要快捷键、token 数和非当前成员，不能隐藏
  当前身份、控制范围、关键失败或输入光标。成员条不无限换行挤占正文。
- 实施默认验收尺寸：110×34、80×24、60×18，以及 40×12 的退化状态。小到无法安全
  显示时给出扩大窗口提示，不能错位发送输入。字体宽度用 Unicode 单元格计算。

## 滚动与恢复的硬边界

- 沿用 `Surface` 的正常缓冲区和 committed-output 边界，结算内容一次性追加。
  不使用 reverse-index 把旧历史推开，也不通过重播日志来实现底部对齐。
- 刚提交的输入与最新输出应连续出现在活动区之前；活动区随内容收缩。关闭菜单、
  工具结算和多行输入收回后，不在最新回合与输入区之间遗留大片空白。
- 不按刷新心跳写换行；只更新仍在活动的区域。窗口缩放、切换视图、开关详情和重连
  都不能制造重复旧日志、旧编辑器或启动标识。
- 原生终端的回看位置和自动回流仍由终端管理，本产品不声称能跨终端锁定滚动位置。
  不用鼠标滚轮捕获替换原生历史，不为了跟随输出模拟另一个终端。
- 新客户端维持最近 20 个结算块、最多 200 行的恢复限额与恢复标记；完整历史不删减。

## 实现边界与交付

复用 Rust、Ratatui/Crossterm、`ViewTarget`、持久事件和统一 transcript 投影。
不改 IPC 协议或模型工具定义来满足视觉变化，不新增插件、终端模拟器或 worktree。
当前 `render.rs` 集中处理了布局/菜单/输入/底栏，`activity.rs` 同时混入成员及诊断；
`transcript.rs` 同时负责记录与文本呈现。实施时按布局、成员条、状态、摘要职责拆分，
不要把新功能继续堆入这些文件，也不要引入平行的旧/新渲染实现。

可由实施者决定：文件拆分、色值微调、可靠的省略算法和必要的缓存。以上用户行为、
控制范围、事件归属、失败可见性及预算边界不可作为实现捷径自行删减。

验收应包含：

1. 问候与知识问答不扫描项目/派工；回车发送可见，结束后能直接继续输入。
2. 主控与两成员、独立草稿、局部/整队控制、任务更换、归档与迟到回执均无串视图。
3. 文件/搜索/补丁/命令的成功、失败、取消、未知和源截断；分组不丢身份或错误。
4. 同一事件流的实况与重放使用同一摘要规则；并发结算、重连和菜单缩放不重复输出。
5. 原生历史和超过 300 条的详情查询、中文/多行、输入恢复及上述四种窗口尺寸。
6. 完整锁定工程回归、fmt、严格 Clippy、release 构建；安装后的实际 PTY 验证与字符
   网格检查。原生 Terminal 仍受此前 Computer Use 明确拒绝的限制，不能将 PTY 算作
   原生窗口验收或绕过访问限制。
7. 安装前留存已验证旧二进制，新版原子安装；现有后台进程、用户未提交文件及冻结
   研究保持不动。更新使用文档、进度和本次证据，不把视觉回归通过当作模型质量提升。
