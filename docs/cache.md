# KV Cache Hit

2026-10-22 用户将缓存命中率提出为关键要求。本次修改发生在研究程序冻结之后：
保留集、冻结程序、账本和原有结果不变，缓存优化按独立工程变更验证，不能用旧研究结果
声称新实现已经提升命中率、速度或质量。

## 实际基线

从 `artifacts/campaign/sessions.sqlite` 的 Usage 事件计算，截止事件序号 20382：

| 范围 | 已报告请求数 | 输入 token | 命中 token | 输入加权命中率 |
|---|---:|---:|---:|---:|
| 全部会话 | 944 | 13,568,395 | 6,823,424 | 50.29% |
| 开发集 | 396 | 6,390,595 | 3,179,776 | 49.76% |
| 保留集 | 325 | 5,087,360 | 2,262,144 | 44.47% |
| 主代理 | 819 | 12,898,132 | 6,349,696 | 49.23% |
| 独立验收 | 90 | 597,480 | 444,416 | 74.38% |

口径为 `sum(cached input) / sum(input)`，输出 token 不进入分母，不平均每个请求的百分比。
这些计数只包含会话事件里供应商返回的用量；没有用量的失败请求和未写入会话事件的独立探针
不在分母内。不能因此将失败请求视为免费。原始统计：`artifacts/cache/baseline.json`。

旧程序的主代理相邻请求共 789 次，474 次改变了 `instructions`：首次变化在文件/依赖范围
373 次、计划 62 次、需求 31 次、用户消息 8 次。工具定义没有变化。这证明旧实现频繁破坏
相同前缀，但不能据此量化这些变化各自造成了多少缓存损失。

## 请求组织

DeepSeek 自动缓存相同前缀，持久化和命中属于 best effort；缓存生成需要时间，闲置缓存也会
被清理。固定每次请求的格式，比加一个不存在的“开启缓存”参数更关键。
[官方缓存规则](https://api-docs.deepseek.com/guides/kv_cache/)

`instructions` 作为第一条系统消息，仅保留稳定角色规则。目标、当前需求、计划、问题、
AGENTS/Skills 指引、任务和依赖范围放进历史末尾的状态消息。第一次发送完整快照；以后只
发送改变的顶层部分，未变化时不追加消息。`set` 整体替换对应部分，`remove` 显式删除部分；
空对象、空数组也是有效替换，避免旧约束或旧授权残留。

状态使用 API 支持的 `developer` 消息（DeepSeek 按 user 处理），不改变前面的指令和工具
定义。保留完整 reasoning、模型输出和工具结果；每批工具结果全部落定后才追加状态。
状态只是报告当前事实，不能授予外部操作权限或将模型假设变成用户要求。
[Responses 格式](https://api-docs.deepseek.com/api/create-response/)、
[思考与工具历史](https://api-docs.deepseek.com/guides/thinking_mode/)

状态与对话一起持久化，重连不重复插入；需求或文件哈希变化仍按原规则做新鲜度检查。
压缩会明确切断旧前缀，随后重新发送完整当前状态，不依赖摘要猜测最新需求。顶层部分仍会
整体替换，例如持续增长的文件指纹表；长会话仍需监测上下文增长与压缩频率，不能为了追求
高命中率无限保留过期上下文或放松检查。

## 观察与复跑

终端顶栏显示 `KV hit`，`/budget` 显示命中数、已报告输入数、未命中数和加权比例。数据来自
Responses 的 `usage.input_tokens_details.cached_tokens`。恢复旧版会话时，如果旧快照没有
累计缓存统计，显示的比例只覆盖升级后已记录用量；缺失用量会明确标注。历史全量统计用：

```sh
python3 scripts/cache_report.py --database ~/.loh/sessions.sqlite --requests
python3 scripts/cache_report.py --database artifacts/campaign/sessions.sqlite \
  --requests --output artifacts/cache/baseline.json
```

可以用 `--session <完整会话ID>` 限定范围。脚本只读数据库与请求文件，不发 API 请求，不输出
原始任务内容或凭据。请求文件缺失时单独计数。请求结构统计表示缓存复用的条件，不是服务端
实际命中率。金额预算仍按保守上限预留，任务 token 预算也仍包含命中的输入 token。

## 验收边界

回归覆盖计划与文件观察后的完整请求前缀、reasoning 原样保留、状态序列化恢复、需求修订、
空状态/删除、压缩重建、工具配对、加权统计和重放去重。原测试已先复现系统前缀变化，修复后
再验证。`cargo test --all-targets` 共 138 项通过，严格 Clippy 通过。测试包含真实 localhost HTTP、
进程恢复及 PTY 输入，模型行为使用夹具；并不等于新状态格式的真实模型质量验收。
日志和构建结果见 `artifacts/cache/`。

尚未做修改前后的真实供应商对照，因此**优化后的命中率和延迟提升均未知**。当前 50 RMB
总预算的保守可用余额不足下一次请求预留；没有额外调用，也没有清除不确定费用。后续实验应
预先固定非保留集任务、模型、工具、上下文上限与等待间隔，记录实际输入/命中 token、首字
延迟、总耗时、压缩次数和外部验收；保留冷请求，按任务配对比较，避免把共享缓存预热当作
机制收益。
