## 实现取舍

- 活动成员的 Skill 沿用其当前分配已有的能力，在工具结算后执行，并重新检查任务、
  路径与权限。空闲或归档成员、显式只读工作流使用只读上下文。这样保留已授权工作的
  能力；如果任务绑定或结算出错，会带来范围漂移，因此加入任务版本、正文哈希、暂停、
  独立回合和真实范围写入检查。
- 后台进程在应用指令中途崩溃时，保留原文及已知结果，报告应用结果不确定，并隔离同一
  请求尚未执行的部分。需要确认的工程意图形成核对问题。这样避免盲目重放造成重复效果；
  代价是这类异常恢复需要一次明确核对。正常断线通过同一请求 ID 去重续接。
- 同一成员的连续 Skill 按后台接收顺序处理：当前指令至少取得一次有效模型响应，且该
  响应产生的工具全部结算后，才接纳下一条。正文、参数和来源保留在上下文历史里。
  这样避免未执行的指令被覆盖，也不必等待整个任务结束才处理下一条；这个边界若处理
  错误，可能漏掉多步指令或在取消后错误推进，因此单独检查队列顺序、取消、重载和任务
  版本变化。“已应用”表示指令进入执行上下文，任务完成仍由需求与证据验收决定。

## 独立验收边界

**原生 Terminal 窗口尚未验收。** 本轮 Computer Use 请求访问 `com.apple.Terminal`
时明确返回：`Computer Use is not allowed to use the app 'com.apple.Terminal' for safety reasons.`
因此没有使用 AppleScript 或其他路径绕过限制。启动参数、引用转义和失败回退使用注入的
模拟进程调用检查；实际 macOS PTY 的字符网格也不能代替原生窗口操作和视觉验收。

**真实 Flash 团队协作尚未验收。** 本轮开始时，50 元共享账本可用余额为
0.00308728 元，已用与不确定费用均保持原口径。本轮没有发起收费试验，也没有重置账本。
本地固定响应服务只能验证状态、协议和终端行为，不能证明模型会正确分工、沟通或修复。
冻结研究版本与既有对照实验结果保持独立。

## 手动原生窗口检查

在安装了 pexpect、pyte、Pillow 的 Python 环境里，从本仓库运行：

```sh
python tests/pty/team.py --binary /opt/homebrew/bin/loh --serve
```

这会启动独立临时目录里的本地固定响应服务和团队，打印 main、Ada、Bob 的连接命令。
它不会自动打开 Terminal，也不使用真实 API 密钥；输出始终标注 OFFLINE FIXTURE。
在三个原生终端窗口分别执行打印的命令，然后检查：

1. 主窗口能看到团队总览；成员窗口显示自己的身份、任务、工具过程与控制范围。
2. 成员窗口 Ctrl-C 只暂停该成员；主窗口 `/team pause` 暂停整队，恢复后局部暂停仍保留。
3. 输入中文与多行草稿、调整窗口大小、打开历史再返回，编辑器和成员归属保持清楚。
4. 关闭一个成员窗口后，用原命令重连；后台任务仍存在，历史不重复追加。
5. 在主窗口显式执行 `/agent Ada --window`，检查 Terminal 打开与连接；失败时应显示可复制命令。

在 fixture 所在终端按 Ctrl-C，只清理该 fixture 的后台进程、服务和临时目录。
这份步骤供人工补验，不能将尚未执行的步骤计作通过。
